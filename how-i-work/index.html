Method

How the work gets made

Claude CodeDaily, 18 monthsSept 2026

The output was never the hard part.

Every marketer has the same leverage now, so producing more stopped being interesting about a year ago. What actually separates one AI workflow from another is whether anybody catches it when the output is wrong, because it is wrong often and it is never uncertain about it.

So this page is not a list of tools. It is what I do inside one.

What I do
Decide what gets built, then reject it until it is right. I do not write the Python and I am not going to pretend otherwise.
Where the value is
Every decision in the Payload build is mine and so is every catch below. A model will hand you a fabricated statistic and a stretched image with exactly the same confidence it hands you good work.
Why it matters
This is what running a team looks like now. Brief it, read what comes back, know which part is wrong, and write down the reason so it does not come back.
01

What I actually caught

These are from one project, over about two weeks. None of them were flagged by anything automated at the time. They were flagged by reading the output and knowing it was wrong.

01

A qualification gate that did not gate

I answered the form as a pre-launch company and still reached the calendar. The routing logic was correct; the button had never been told to change. A gate that lets the wrong people through is worse than no gate, because now the page is lying.

02

Every image on a page, stretched

The case study looked wrong to me before I could say why. Each screenshot was drawing at roughly twice its correct height because of one missing CSS line. The files were fine, the markup looked fine, and nothing reported an error.

03

A statistic that was invented

An email opened "nine times out of ten that is not disinterest." Nobody can source that. It sat inside a package whose entire argument is that every number in it is checkable, and it read perfectly well, which is the problem.

04

Copy that quietly argued against me

A disclaimer said the findings were "things anyone can reproduce." Technically true, and it hands away the work. What I found had been public the whole time and nobody had gone looking, which is the opposite point.

05

A person's surname, made up

A draft email referenced a friend by a last name that is not his. It was one word in a message headed for a real inbox at a company I want to work for, and it was presented with total confidence.

06

412 subscribers, when it was 375

From earlier work. My own LinkedIn and my own resume disagreed about my own list size, because one counted everyone ever added and the other counted the peak. I would rather find that than have an interviewer find it.

02

Then the reason gets written down

A catch that only happens once is luck. What turns it into a system is that every one of those becomes a written rule, in a file that loads before any work on that project starts.

There are forty of them now, across 1,135 lines, and every single one exists because something went wrong first. The stretched images produced a rule. The invented statistic produced a rule and a check that greps for that exact phrasing. The surname produced a rule about names in outreach.

That is the actual difference between using these tools a lot and getting something out of them. The model does not remember last Tuesday. The written rules do.

# from the project rule file, written to the next session

24. Internal reasoning is not customer copy. If a line explains our
    thinking rather than telling the reader what happened and what to
    do, cut it.

31. Prose tells to hunt before shipping: a paragraph that restates a
    later section, a setup line that announces something good is coming
    instead of saying it, a number more precise than its source.

I did not write these files by hand. I caused them, by rejecting the same kind of work enough times that the reason had to be recorded.

03

And the checks come last, not first

There is a script that runs against every page before anything is published. It opens a real browser, scrolls the whole thing, and measures what actually rendered: colour contrast on every piece of text, horizontal scroll at six screen widths, images against their real file dimensions, and whether any subject line on a preview page has drifted from the email it claims to show.

Every check on that list is there because something got past me once. It greps for invented statistics because of number three above. It compares image dimensions because of number two. It fails the build if a consent checkbox ever ships pre-ticked, because that is the kind of thing nobody notices until it is a legal problem.

I could not write that script from scratch. I know exactly what it needs to look for, which is the part that took a year.

04

Why this is the job now

A marketing manager's relationship with output has not really changed. You set the brief, you hold the standard, you send work back, and you make sure the same note never has to be given twice.

That is what I have been doing every day for eighteen months. The difference is only in how fast the work comes back and how confidently it is wrong when it is wrong.

What I would bring to a team is not that I can produce a lot. Everybody can now. It is that I have spent a year building the judgment to tell which of it is worth sending, and the habit of writing the reason down so nobody relearns it.
